# M09 检索开发集数据卡

文件：`data/samples/m09-retrieval.json`，schema=m09-cases-v1，公开合成开发集。

- 来源：人工按M08生成器的固定30篇v1 Markdown语料编写24个问题；两租户各12题，题目与标签不是从当前检索排名反推。
- 每租户8道有答案题：CRM 3、HCM 2、SCM 3；另4道空标签题：错误角色、未生效、无答案、跨租户请求。
- 跨租户题使用正常sales角色，明确请求另一租户的文档ID，避免被空角色范围提前挡住。它可能返回本租户的相似候选；应记录误召回并核对所有hit的tenant，而不是把候选出现当作越权。问题写“只查另一租户”不会让本课检索器自动实现意图识别或生产认证。
- 标签是tenant_id/document_id/version。角色sales/hr/procurement/employee与as_of固定，不表示真实用户通过认证。空标签表示在该题范围内期望不返回文档，不表示运行失败可当正确拒绝。
- 生成器对两租户复用类似业务规则，能检查身份范围，但不能模拟复杂语义、真实权限或法律制度。
- 适用：固定基线比较、权限/日期边界、文档级去重指标、失败分母与原文引用检查。不适用：模型泛化能力、生产质量、企业知识覆盖或安全认证。
- 不作为隐藏测试集；没有训练/验证/测试切分，也没有真实用户资料。后续应新增未参与调参的题目，人工双人标注并保留分歧。
- 与索引绑定：v1语料与本题集配套。更新文档或ACL后需明确更新标签/新建评估版本；不能让旧标签误判新政策。
- 本课k表示chunk预算，在前k块内按文档/版本去重。异常有答案题记0保留分母；空标签题报告候选出现率、干净拒绝率与错误数，不把候选出现率直接叫越权率。
- 报告分别标记fixture与真实模型；固定cases/index/source/model/code摘要。两种kind不得作为同模型优化对照。

操作与人工核对要求见[第9课](../tutorials/09-enterprise-rag.md)。
