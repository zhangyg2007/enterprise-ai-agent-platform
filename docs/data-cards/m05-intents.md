# M05 意图分类合成数据卡

此卡描述 M05 生成器的数据约定，不代表某个数据包已在服务器通过验收，也不代表已经完成人工复核。实际状态以该包 manifest、validate 输出和独立人工报告为准。[操作教程](../tutorials/05-finetune-data.md)

## 身份与来源

| 项目 | 说明 |
|---|---|
| 名称 | M05 intents，中文企业请求分类教学数据 |
| 数据版本 | 本课首版；具体生成器版本、seed 和摘要见 manifest.json |
| 默认 seed | 42 |
| 生成方式 | 项目内维护的规则与表达模板，程序化组合合成场景；模板由AI辅助撰写，仍需人工语义复核 |
| 原始业务数据 | 无；不读取 M02 数据库，不导出客户、员工或库存记录 |
| 保护集 | data/samples/m04-intents.jsonl，仅读取用于排除重合并记录字节摘要 |
| 目标契约 | M04 SYSTEM_PROMPT 与 intent/customer_id/product_id/action 四字段 |
| 可复现条件 | 相同生成器代码、seed、M04 题集和提示词；manifest 不加入实时生成时间 |

所有客户、商品、员工和工单编号都是合成标识，不承诺对应 M02 表中的现存记录。输入不含真实姓名、联系方式、实际薪资、密码或业务余额；答案不提供数据库事实。敏感请求只用于学习分类拒绝，不包含真实敏感内容。

许可记录：仓库目前尚未指定独立代码或数据许可证，本数据卡不新增授权条款。

## 用途和不适用范围

适用于学习标注、分组切分、格式转换、完整性验收，以及后续小规模监督微调实验。目标是输出请求意图、编号与候选动作。`query` 不是授权结果；实际应用必须独立认证用户、检查租户和访问权限，再调用受控工具。

不用于真实库存或假期问答、不作为数据库内容备份、不作为企业身份认证依据，不支持证明生产可用性或真实业务准确率。不能把对这批合成保留集的高分当作真实客户分布上的泛化证据。

## 数量、类别与切分

30 个场景组，每组绑定客户、商品、员工、工单实体，每组 8 类、每类 2 个表达，合计 480 条。8 类包括客户查询/缺编号、本人假期/他人假期、库存查询/缺编号、敏感请求拒绝和多业务澄清。每类共 60 条，刻意平衡，不模拟实际业务频率。

| 分区 | 组数 | 样本数 | 每类数量 |
|---|---:|---:|---:|
| train | 21 | 336 | 42 |
| validation | 6 | 96 | 12 |
| test | 3 | 48 | 6 |

按 seed 与 group_id 的 SHA256 排序分组分配，然后使用各分区分别编写的表达模板。相同实体及关联组不得跨分区；规范化文本与去数字模板指纹也不能跨分区重合。M04 输入和实体被排除。此规则减少明显泄漏，不证明所有语义近似或来源相关性已消除。

validation 用于后续开发选择；test 不注册进 dataset_info，不用于训练、调参或挑 checkpoint。为了格式互验保留 test 的两种导出文件，但“文件存在”不是使用许可。保护集已公开、规则和模板也公开，因此 test 不是真正隐藏的外部测试集。

## Schema 与文件

canonical 的 `samples.jsonl` 每行有 `sample_id/group_id/split/category/template_id/entities/prompt/answer`。`prompt` 是原始中文请求，`answer` 是四字段对象；其他字段支持追踪、分组和校验。provenance 来源说明由本卡及 manifest 记录。

三分区分别导出 Alpaca 与 ShareGPT，共六个 JSON 文件。Alpaca 包含 instruction/input/output/system；input 为空，output 是 JSON 字符串。ShareGPT 包含 system 和 conversations，后者只有 human 与 gpt 两条消息。system 与 M04 相同；两种格式承载同一批数据，训练时只选一种。

dataset_info 仅注册 `m05_train_alpaca`、`m05_validation_alpaca`、`m05_train_sharegpt`、`m05_validation_sharegpt`。48 条 test-cases.jsonl 采用 M04 评估结构；24 条 manual-review-template.csv 是人工抽样模板。manifest 记录 seed、生成器版本、保护集与提示词摘要、文件摘要、计数和完成状态。

## 标注与清洗标准

标签按 M04 固定优先级：违规或敏感请求拒绝，多业务澄清，再按单业务规则分类。缺失、无效或多个业务编号不得猜测；本人与他人的假期请求需分别处理；员工和工单编号不写成 customer_id 或 product_id。答案恰好四字段，ID 为 null 或合法正整数，拒绝多余解释和额外字段。

生成及验收检查结构、重复、标签关系、实体/组/文本/模板边界、M04 重合、格式等价、注册路径和文件完整性。它不是自然语言语义审核器。标注员应另外检查语义与规则一致性；不能确定时在报告中标 `needs_review`，交由规则负责人裁定，不能擅自把所有争议变成 `clarify`。

抽样按 8 类 × 3 分区各一条，共 24 条，固定生成规则下可复现。模板复制到 reports/local 后填写 reviewer/decision/note，不修改原包。报告中应保留审核人、样本 ID、结论、问题、裁定及未决项。发现系统性错误时扩大复核并重新生成新版本。抽样表存在不表示审核已完成，24 条抽样也不等于全量人工验收。

## 已知限制与维护

- 样本来自少量模板，没有真实口语、行业缩写、拼写噪声、长对话和复杂跨业务上下文；类别平衡与真实分布不同。
- 只覆盖选定的八类，没有穷尽 M04 规则或真实攻击边界。敏感拒绝例子不能证明提示注入防护能力。
- 分区实体与完整模板隔离，但仍共享意图语义和生成机制；仅换 seed 不能创造独立现实来源。
- test 仅 48 条，且模板公开；反复查看其失败并调整模型会逐步把它变为开发集，需要新的保留集。
- 字符检查不代表 token 检查；真实 tokenizer、聊天模板、截断及训练加载兼容性留到 M06 验证。
- SHA256 摘要可检测意外改动，不是来源签名或防恶意篡改证明。自动验收也无法代替人工语义复核。

修改业务规则、提示词、模板或格式时，保留旧包，更新代码与数据卡，以新目录重新生成和验收。历史报告不得悄悄套用到新版本。出现授权或真实个人数据问题时应停止使用受影响版本、记录来源和影响范围，并按项目数据治理流程处理；本课不采集这类真实数据。
