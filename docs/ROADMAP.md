# 课程路线与模块交付计划

创建日期：2026-10-15；更新日期：2026-10-16。状态：课程方案已确认；M01–M02 的代码与教程已撰写，服务器验收待执行。其他模块仍为计划，不视为已交付。

## 1. 学习目标和主线选择

最终能够独立完成一次小型 FDE 项目：理解企业问题，接入业务数据，建立可验证的模型/RAG 基线，构建有权限边界的 Agent，在 Ubuntu 部署，并交付运行手册和评估报告。

三条可选路线：

| 路线 | 优点 | 代价 | 本项目安排 |
|---|---|---|---|
| 单机 PostgreSQL + pgvector + Python + LangGraph | 组件少，数据和权限机制能一起学习，适合现有服务器 | 不代表分布式高可用架构 | 主线 |
| MySQL 业务库 + 独立向量数据库 | 贴近部分企业现状 | 增加同步、备份、权限与一致性复杂度 | 学完主线后的接入扩展 |
| Kubernetes + 多模型服务 + 分布式数据平台 | 可演练规模化运维 | 首次学习成本高，单卡资源受限 | 后续专题，不作为起步依赖 |

主线采用 Python、PostgreSQL、pgvector、LLaMA-Factory、Qwen、LangGraph 1.x、FastAPI。M01 应用环境先用 Ubuntu 默认 Python 3.12，训练环境后续单独使用 3.11。版本在对应模块实施时锁定并验证，当前设计不冒充已测试兼容矩阵。

Hadoop 基础可迁移到分区、血缘、批处理与增量处理；第一轮不要求安装 Hadoop 或 Spark。先用 Python 完成小规模可观测流水线，再做大批量扩展。

## 3. 依赖与里程碑

- 里程碑 A：M00→M01→M02→M03→M04。获得可复现的企业数据和模型调用基线。
- 里程碑 B：M05→M06→M07。完成一次有对照评估的微调，保存可恢复的 adapter 和配置。
- 里程碑 C：M08→M09。完成可引用、可更新、可控制访问范围的知识库。
- 里程碑 D：M10→M11→M12→M13。完成业务 Agent、运行手册和 FDE 交付包。
- M08/M09 技术上不依赖微调成功，可以在训练等待期间学习；完整业务应用需具备模型调用、数据库工具和知识检索三项能力。

## 4. 第一批实现范围

设计确认后，先实施 M01–M02，再推进后续模块，避免一次写完全部教程却缺少运行证据。

第一批具体交付：

1. 项目目录、Git 忽略规则、配置模板、应用环境依赖清单。
2. Ubuntu 安装手册，所有命令明确标注“服务器执行”；保留已有 Ollama。
3. PostgreSQL + pgvector 的 Compose 配置；默认只监听服务器回环地址。
4. CRM/HCM/SCM 初始化迁移和小规模合成数据生成器。
5. 三条业务查询：客户订单概况、本人假期余额、库存可用量。
6. 数据生成、外键、权限与可重复执行的检查方法。
7. 学习者提交运行结果后，记录服务器验证结果并修正文档。

每批交付分开标注“文件已撰写”“静态检查已执行”“服务器已验证”。GitHub 提交/推送前审阅具体变更；不默认执行部署或合并。

## 5. 教程统一格式

每章采用以下结构：学习目标 → 业务问题 → 原理与术语 → 前置条件 → 操作位置与步骤 → 预期结果 → 验收 → 常见故障 → 恢复操作 → 练习 → 官方资料。

每个关键配置同时解释作用、为什么这样选、调大会怎样、调小会怎样。例如解释 batch size 与梯度累积，而非仅提供一份可复制 YAML。

每个业务案例至少覆盖正常请求、信息缺失、权限越界、恶意文档内容、工具故障、审批拒绝和重复执行。练习先给问题，答案与解释独立呈现，保留自主实践空间。

## 6. 课程质量目标

以下为教学验收目标，需在固定数据和设备配置下测量，不是模型能力承诺：

- 数据层：固定种子可复现；金额与库存确定性计算准确；外键无悬空记录。
- 微调层：格式有效率、字段准确率、拒答行为分别报告；效果没有提升也保留失败分析。
- 检索层：固定问题集比较精确检索、近似检索、融合与重排，不预设某种方案必然更好。
- Agent 层：越权测试必须全部拒绝；审批拒绝不产生业务写入；重复批准只执行一次。
- 部署层：备份在独立测试库完成一次恢复；重启后可恢复待审批线程。
- 质量报告保留样本数、模型/数据/代码版本、配置、硬件、原始结果和失败案例。
