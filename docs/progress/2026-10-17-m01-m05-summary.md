M04和M05使用相同的四字段业务契约：intent、customer_id、product_id、action。它训练/评估“识别请求并提取参数”，不让模型记忆实时库存或假期余额。后续应用仍须通过权限校验调用业务工具。

## 2. M05的具体交付

- 30个关联场景组，每组8类请求、每类2种表达，共480条。
- 先分组，再为train/validation/test使用不同表达模板；21/6/3组对应336/96/48条。
- 检查实体、场景组、规范化文本和去数字模板指纹，防止明显交叉泄漏；保护M04题目及其期望答案中的客户/商品编号。
- Alpaca与ShareGPT是同一份标注的两种表示，训练时只选一种，不能同时加载造成重复加权。
- dataset_info仅注册train/validation的四个格式项，test不注册训练；48题test-cases兼容M04评估器。
- 输出manifest、原始标注、导出文件及摘要。已有目录拒绝覆盖，生成中断保留building状态。
- 提供24条人工复核模板。它不是已签字的人工审核结论，实际填写由学习者完成。

这些样本来自公开合成模板，适合学习流程。即使分组检查全部通过，也不能证明真实企业语义分布独立或上线准确率。

## 3. 遇到的问题及处理

| 问题 | 影响 | 处理与目前状态 |
|---|---|---|
| `qwen3.8:27b`真实身份未核实 | 不能据名称选择HF训练底座或推断架构 | 保留用户标签；M00/M04读取真实清单、digest、模板和来源，待服务器提供证据 |
| CUDA13含义不明确 | 驱动显示的CUDA能力可能与Toolkit/PyTorch运行时混淆 | 教程分别检查；未在Windows或服务器擅自修改CUDA |
| M03版本冲突事件未保留event_id | 改版本后可能复用同一事件ID重新生效 | 独立审查发现；先复现，再保留冲突事件ID，回归通过 |
| Windows临时目录与文件锁/编码 | 测试文件可能无法清理，或UTF-8按GBK读取 | 显式关闭SQLite连接，使用工作区临时目录，测试显式UTF-8 |
| M04测试替身掩盖客户端缺base_url | 真正组合客户端和运行器时会失败 | 新增真实客户端加内存HTTP的集成测试，复现后修复 |
| M04题集读取两次 | manifest摘要可能不对应实际评估内容 | 使用同一字节快照解析和计算摘要，回归通过 |
| M04异常Unicode或极大token计数 | 写记录或计算吞吐时中断，丢失后续题目 | JSON转义保存；无效吞吐降级null；新增回归通过 |
| LLaMA-Factory固定验证与随机切分可能混用 | 原先按组隔离的验证设计可能被破坏 | 明确使用eval_dataset和val_size=0；检查注册映射，M06再验证实际加载 |
| 两种数据格式容易重复加载 | 同样样本被重复训练，夸大数据量 | 教程明确二选一，导出等价检查通过 |
| 子代理额度中断 | 教程与独立审查未能在上一轮一次结束 | 接管已有文件并继续验证；最终审核状态以模块验证记录为准，不把中断说成审核通过 |
