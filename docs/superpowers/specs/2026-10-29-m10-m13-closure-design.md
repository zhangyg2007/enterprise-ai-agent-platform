# M10–M13 原目标闭环设计

沿用用户已确认的[总体设计](2026-10-15-enterprise-ai-platform-design.md)和[完整性审核](../../validation/2026-10-29-m10-m13-audit.md)，按用户本轮指示补齐未完成的实现、教程、验证与GitHub同步。服务器实测和真实客户签字无法由本地测试替代，保持待验收。

1. **可信审计与租户隔离**：受认证且校验后的业务thread标识进入HTTP结构化日志，与M11业务审计中的tenant/request_id对应；日志不包含消息正文、凭证或任意未校验输入。记录失败/拒绝和重试的关联号；每租户仅可读取本租户的进程内指标，不宣称分布式指标或跨重启持久。原业务审计事务不改变，历史数据与checkpoint兼容。
2. **三业务闭环**：利用M10受限模型规划、M09受ACL/时效/完整性约束的文档检索、M11冻结业务数据与人审事务，接通提案、证据、审批与重试。模型与文档仅作为不可信输入；校验身份、角色、字段、可信数据版本和有效引用后才允许创建草案；无证据/权限/数据或异常拒绝写入。执行前重查快照与政策版本，按幂等契约避免重复。跨租户与注入负例覆盖三场景。
3. **四组评估**：固定输入、业务工具快照、模型及索引身份与生成参数；四种实验臂逐题记录模型原始输出、证据、错误与延迟，失败不从分母消失。无GPU或真实模型时使用明确标记的可控测试替身，只证明管线不提供真实分数；服务器配置与操作指南应可复现。
4. **高层/异步教学**：以固定兼容的LangChain真实`create_agent`与LangGraph `ainvoke`提供最小可执行示例，使用离线可控模型证明框架行为，绝不允许模型自行绕过授权/审批。
5. 每一批TDD和实际命令验证，新增材料同步Filelist/README/路线，验证和独立review分开。GitHub同步仅在质量门禁通过后推送开发分支并创建/更新草稿PR；不默认合并或部署。
