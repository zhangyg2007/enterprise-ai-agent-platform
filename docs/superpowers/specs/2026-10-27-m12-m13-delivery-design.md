# M12–M13：应用服务与 FDE 交付设计

沿用用户已批准的 M00–M13 总设计及此前“完成 M12/M13 并同步 GitHub、Filelist”的要求，不新增必修模块。

M12 将 M11 的确定性审批图封装为 FastAPI 服务：Bearer 凭证在服务器映射为合成实验身份或 PostgreSQL service；HTTP 不接受用户自报租户、角色或数据库地址。保留 M11 独立经理审批、线程授权、幂等、锁和失败重试。提供严格请求模型、请求体上限、单进程限流、脱敏日志、请求关联号、存活/就绪探针与受保护计数器。单进程、回环地址部署，SSH 隧道访问；公共互联网入口与企业 SSO 为验收前的后续集成，不宣称已提供。

备份实验在 M11 操作锁内用 SQLite backup API 一致复制三库，包含格式、lab_id 和 SHA256 清单，恢复到不存在的新目录；拒绝覆盖、损坏、混库和符号链接。PostgreSQL 给出独立数据库恢复步骤与运行证据表，真实 PG/Ubuntu 仍待服务器实测。升级/回滚练习使用版本化代码目录，不自动回退数据库。

M13 独立交付中文教程、需求访谈、数据契约、验收矩阵、四组模型对照、成本预算、演示与交接模板。每项区分目标/实测/未执行；不生成虚假模型指标、客户签字或服务器结果。

文件边界：主执行者拥有 M12 源码、测试、依赖、运维材料和所有总导航；独立作者只拥有 M13 教程与 docs/fde 下模板，无共享代码改动。verification 由主执行者实际运行；最终 review 用新上下文。

验收：真实 ASGI + M11 图实验（跨租户、跨用户、自批、坏输入、重复请求、拒绝无效果、崩溃重放）；备份恢复后完成暂停审批且只有一笔效果；文档命令与本地链接检查；完整可用回归。未具备的服务器、GPU、PG、TLS/SSO证据在交付记录中明示。
