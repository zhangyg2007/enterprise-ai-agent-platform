# M10 LangGraph Basics Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans inline with TDD, then one independent final review.

**Goal:** Build a real, bounded StateGraph connecting strict model decisions to read-only database/RAG tools.
**Architecture:** Trusted CLI principal bound outside graph input; plan -> bounded tool/retry -> deterministic finish; updates stream. Fixture uses genuine M09 retrieval, live uses existing Ollama and DB.
**Tech Stack:** Python3.12 candidate; langgraph1.0.2, langchain-core1.6.13, checkpoint3.0.1/prebuilt1.0.13/sdk0.2.15.
**Spec:** ../specs/2026-10-22-m10-langgraph-design.md

## Global Constraints

- No writes, checkpoint persistence, approval or API authentication in M10; M11/M12 own them.
- Model cannot set tenant/reader/roles/employee/SQL. Revalidate exact tool+arguments at runtime.
- One planning call, at most1..3 read-only tool attempts, input500chars/output64KiB, soft deadline1..300seconds. No hard cancellation claim.
- No model downloads/services on Windows. Framework development dependencies only in ignored test directory; Ubuntu acceptance remains separate.
- Every checkpoint updates Filelist. Main remains unmerged; M09 learning branch stays stable.

## Review Focus

Extra model fields/SQL/write commands, principal mismatches, retrying permanent failures, stale RAG, leaked exception text, output overflow, empty results, deadline after blocking call, actual framework invoke/stream rather than a homegrown scheduler.
