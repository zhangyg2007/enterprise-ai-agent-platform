# M01–M02 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** 提供可在 Ubuntu 24.04 上复现的 PostgreSQL/pgvector 教学环境、两租户合成 CRM/HCM/SCM 数据、三种查询及数据库验收入口。

**Architecture:** 数据生成与校验只使用 Python 标准库，数据库工具使用 psycopg。Compose 只启动 PostgreSQL；数据库角色绑定固定教学租户和员工，RLS 不依赖客户端可伪造的会话变量。安装和集成验证在服务器执行，本地只用已有工具检查文件和纯 Python 行为。

**Tech Stack:** 应用环境 Python 3.12（支持 3.11–3.13）、PostgreSQL 16、pgvector 0.8.2、psycopg 3、unittest、Docker Compose。

## 1. 文件与执行边界

- 根配置：`.gitattributes`、`.env.example`、`compose.yaml`、`pyproject.toml`，由主代理串行维护。
- 数据库：`infra/postgres/init/00-roles.sh`、`10-schema.sql`；`src/enterprise_ai/db.py`、`queries.py`，由主代理维护。
- 合成数据：`src/enterprise_ai/data.py`、`tests/test_data.py`，独立子任务；数据契约见下文。
- 操作教程：`docs/tutorials/01-ubuntu-platform.md`、`02-enterprise-data.md`、`docs/data-dictionary.md`，按已冻结接口撰写。

- 验证：`tests/` 为无数据库测试；`python -m enterprise_ai.db verify` 为真实数据库检查。二者结果分开记录。

## 2. 已冻结的数据契约

生成器接口：`generate_dataset(profile='tiny', seed=42) -> dict`；`validate_dataset(dataset) -> None`（无效抛 ValueError）；`dataset_digest(dataset) -> str`。

顶层字段为 `schema_version=1`、`profile`、`seed`、`as_of='2026-10-15'`、`tables`。`tables` 为下列键到行字典列表的映射，所有列名严格匹配。

```text
core.tenants: id, name
hcm.departments: tenant_id, id, name
hcm.employees: tenant_id, id, department_id, name, email
hcm.leave_balances: tenant_id, employee_id, year, entitled_days, used_days
hcm.leave_requests: tenant_id, id, employee_id, start_date, end_date, days, status
scm.suppliers: tenant_id, id, name, lead_days
scm.products: tenant_id, id, supplier_id, sku, name, unit, unit_price
scm.warehouses: tenant_id, id, name
scm.inventory: tenant_id, warehouse_id, product_id, on_hand, reserved, reorder_point
crm.customers: tenant_id, id, name, owner_employee_id
crm.sales_orders: tenant_id, id, customer_id, order_date, status
crm.sales_order_items: tenant_id, order_id, line_no, product_id, quantity, unit_price
scm.purchase_orders: tenant_id, id, supplier_id, expected_date, status
scm.purchase_order_items: tenant_id, order_id, line_no, product_id, quantity, unit_cost
```

金额和假期天数使用十进制定点字符串，数量为整数，日期 ISO 格式；租户 1/2 的实体 ID 从 1 分别编号。tiny 每租户 20 客户、30 员工、40 产品、100 销售订单、30 采购订单；standard 每租户 1000/500/2000/20000/5000。每个订单 1–3 行；每租户 4 部门、5 或 50 供应商、2 仓库；每员工一行余额。订单状态为 open/completed，采购为 ordered/received，假期申请为 pending/approved/rejected。

## 3. 任务与验证顺序

- [x] T1 根配置与数据库：固定镜像标签，生成凭证，初始化只读角色，创建 14 张表、组合外键、RLS 和索引。不得自动删除卷。配置前先提供凭证生成的拒绝覆盖测试。
- [x] T2 数据生成：先编写确定性、规模、金额、引用完整性、重复键和非法数据测试，观察失败，再实现生成/校验/摘要；运行 `python -m unittest discover -v`。JSON 导出拒绝覆盖已有文件。
- [x] T3 数据库工具：实现 health/load/demo/verify。导入先离线校验，再在单事务和 advisory lock 下 COPY；同摘要重跑返回 unchanged，不同数据集拒绝。动态 SQL 标识符仅从白名单构建。固定查询使用参数化值。
- [x] T4 教程：覆盖新装/已有环境分支、凭证与卷生命周期、三条业务查询、ER 图、数据字典、练习与答案、故障定位、提交证据方法。
- [x] T5 验证：现有 Python 上跑纯逻辑测试与语法检查；真实 PostgreSQL/GPU 测试在本机不执行，提供服务器命令并如实标注。
- [x] T6 独立审阅：需求符合性和代码质量分开检查，两个 pass 均无严重或重要问题；检查报告随本批本地提交保存，发布前展示具体成果。服务器集成仍待用户执行，不包含在此勾选结果中。

数据库验收断言：读角色不是超级用户/表所有者；租户 A/B 各只见自己数据；HCM 只见 employee_id=1；更改自定义 session setting 不能冒充租户；跨租户主外键失败；读角色写入被拒绝；查询金额等于明细精确求和；同数据集重跑行数不变。

三条查询接口固定为 `demo --reader a|b`：客户 1 的订单数量/金额、当前员工 2026 假期余额、产品 1 分仓库存。调用者不能传 tenant_id 或 employee_id 以改变身份；未来 HTTP 认证在 M12 接入，当前角色只是教学账号。

## 4. 实施决策

使用本地 `.worktrees/m01-m02` 隔离开发，不安装任何本地依赖或服务。本批不实现 FastAPI、模型训练、pgvector 检索或生产身份系统；pgvector 仅验证扩展可用。M01 GPU 张量验证由现有 Ollama/后续训练课承接，避免基础数据库课程提前安装训练依赖。

本计划经过范围自查：与确认的首批目标对应；后续模块仍保持路线图状态。不能执行的集成测试明确留作服务器验收，不作为完成声明。
