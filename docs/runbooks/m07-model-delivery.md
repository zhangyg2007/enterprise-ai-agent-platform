## 4. 回滚演练

1. 保存当前 release 与失败证据，停止当前服务，确认端口释放。
2. 选择此前已通过验收的 release；运行 `model_delivery verify`，核对对应底座及 adapter 仍在。
3. 在同一已验证环境用旧 adapter.yaml 或 merged.yaml 启动，记录实际配置路径。
4. 用新的 probe 输出路径验收旧服务，保留启动时间、探针和业务回归结果。
5. 记录回滚原因、耗时、恢复版本和后续修复计划；没有旧版本时写明“无可用回滚版本”，停止上线。

回滚不能通过覆盖新权重来伪造旧版本。API 别名相同也不表示资产相同。目录清理必须另行确认，不在本演练中删除现场。
